# 口播稿：Design Token —— 前端团队的视觉契约

## 第一段：引入问题

你有没有遇到过这种情况？【停顿】

设计师说"把主色改成蓝色"，你在代码里改了十几个文件，上线之后发现——按钮是蓝的，但某个弹窗的边框还是老颜色。【停顿】这就是没有 Design Token 的代价。【重音】两份独立的定义，两张独立的维护表。

## 第二段：核心概念

Design Token 是什么？【停顿】它是设计系统的**原子单位**。【重音】注意，它不是 CSS 变量的简单别名——它是跨越设计与工程的单一事实来源。

## 第三段：三层架构

Design Token 有三层。第一层 Global Token，是底层原子值，比如 `color.blue.500`。【停顿】第二层 Alias Token，是语义化别名，比如 `color.primary`。第三层 Component Token，是组件级覆盖，比如 `button.background`。

这三层有什么好处？【停顿】设计师可以调整全局色板，【重音】不影响组件；也可以在单个组件层面做精细覆盖——不污染全局，也不丢失一致。

## 第四段：工具链与收尾

工具方面，Style Dictionary 是目前最成熟的开源方案。【停顿】它接受一份 JSON 定义，输出 CSS Variables、SCSS、iOS Swift、Android XML。【重音】同一次定义，零人工翻译。

这就是 Design Token 的价值——让设计系统真正成为团队的**契约**，而不是文档。
